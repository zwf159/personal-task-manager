# 拾序 Taskflow

运行在本机的个人任务管理工具：把任务、子任务、执行记录、时间投入和备份放在一个中文工作空间中。Python + SQLite + 原生 JavaScript，无第三方运行依赖、账号或外部数据服务。

## 启动与第一次使用

需要 **Python 3.11 或更新版本**。

1. 克隆或下载仓库；Windows 双击 `start.cmd`，其他系统在仓库根目录执行 `python -m taskflow`。
2. 保持启动窗口打开，用浏览器访问 **http://127.0.0.1:8765**。
3. 点击左侧“项目分组”旁加号创建项目，再点击“新建任务”。
4. 填写名称、备注、项目、优先级和截止日期并保存。
5. 点击任务旁的“详情”，添加清单、记录和时间投入。
6. 点击顶部“个人工作台”，打开目标、习惯、收集箱、笔记、每日计划、周复盘、规则、项目模板、数据健康、数据迁移或日历排程。

首次启动为空列表，不写入示例任务。按 Ctrl+C 停止服务。

端口被占用时运行 `python -m taskflow --port 8766`，改为访问 http://127.0.0.1:8766 。可用 `--database 路径` 指定其他数据库。

## 数据与边界

- 默认数据库 `data/taskflow.db`，完整备份在 `data/backups/`；整个 data 目录已被 Git 忽略。
- 恢复前校验 SHA-256、数据库结构、完整性和外键，只接受与当前结构兼容的备份，先自动创建当前数据的安全备份。不要从其他进程同时写入此数据库。
- CSV 不包含所有关联记录，不能替代完整备份。导出带 UTF-8 BOM 和公式前缀转义。
- CSV 最多 500 行、50,000 字符，另有 64 KB 请求体限制；必须有“任务”列，其余列与导出一致。项目需提前创建；名称、项目、日期相同的任务会跳过；任何错误阻止整批写入。
- 重复任务以原截止日期加间隔生成下一次；无日期时从今天算起。不自动补齐错过的多个周期。重开后再次完成不会重复生成。
- 专注全局只有一个计时，按真实经过时间计入工时，不超过计划时长；不足一分钟不增加工时，重复停止不重复记录。
- 提醒只在服务运行、页面打开时查看，每分钟刷新；不发送邮件、系统推送或页面关闭后的通知。
- 日期和统计按服务器电脑的本地日期；提醒存 UTC，界面显示浏览器本地时间。建议同机使用。
- 服务只监听 127.0.0.1，无多用户认证，不适合暴露公网，也不支持手机通过局域网访问。
- 无 CDN、远程字体或跟踪脚本；参考链接仅存储，服务器不抓取。
- 评论、回收站、模板暂未分页，详情较长、大数据量未压测，见后续计划。
- 工作台的笔记与收集箱每次最多显示最近 200 条，复盘、项目模板和健康报告最多 100 条；规则单次最多匹配 100 个任务。规则需手动执行，不在后台自动修改数据。
- 目标按关联且未删除的已完成任务计数；习惯只能记录今天及过去的真实完成量。笔记以纯文本显示，不执行 HTML。
- 项目模板最多包含 100 个任务，只复制项目内依赖，不复制工时、日志和外部项目关系。应用使用请求编号防止重复创建。
- 可移植数据包最多 5 MiB、10,000 条核心记录，不含全部业务表，不能替代数据库备份。导入只添加独立副本，同名项目改名、同名标签复用；相同任务内容只提示重复，不自动合并。会话一小时后过期，请及时下载回执。
- 日历导入单次最多 200 个独立事件，界面限制文件 40 KB。全天、取消事件会跳过，重复规则和跨日占用事件不支持；结束于次日 00:00 的时段可接受。TZID 依赖本机时区数据库，无法识别时应从源日历导出 UTC。
- 日历安排按服务器本地时区显示，建议同机使用。复制或导入默认遇冲突整批停止，只有明确选择时才跳过冲突项；预览后目标变化必须重新预览。

## 代码结构

| 位置 | 职责 |
| --- | --- |
| taskflow/__main__.py | 启动、端口、数据库路径 |
| taskflow/store.py | SQLite、验证、事务、版本与操作历史 |
| taskflow/query.py | 列表、搜索、分页和导出共用查询 |
| taskflow/server.py | HTTP、请求检查、静态资源白名单 |
| taskflow/assets.py、validation.py、dates.py | 资源清单、共享边界校验、日历计算 |
| taskflow/features/ | 项目、回收站、标签、清单、记录、筛选、依赖、工时、专注、周期、统计、备份、CSV、模板、提醒、链接 |
| taskflow/extensions/ | 十一个工作台业务域，包含路由、校验、业务、持久化和迁移 |
| taskflow/cli.py、commands/ | 本地命令行管理，复用同一业务校验与事务 |
| taskflow/static/ | 中文界面、模块化交互与响应式样式 |
| tests/ | 存储、功能、HTTP、迁移回归 |
| docs/ | API、验收记录、后续计划 |

## 验证

仓库根目录运行：

```sh
python -m unittest discover -s tests -v
```

测试在 data 下创建临时库并自动清理，不修改真实任务；HTTP 测试需允许本机连接。可选安装 Node.js 后对 `taskflow/static/` 下每个 .js 执行 `node --check 文件路径`。产品运行不需要 Node.js。

GitHub Actions 在 Python 3.11、3.14 下执行测试，并检查全部前端脚本语法。实际浏览器验收见 [QA](docs/QA.md)。

## 命令行管理

查询和管理使用同一 SQLite 数据与业务服务。修改或恢复前请先停止网页服务，避免两个进程同时操作备份恢复。

```sh
python -m taskflow.cli --help
python -m taskflow.cli tasks list --status todo
python -m taskflow.cli tasks add "整理本周复盘" --priority high
python -m taskflow.cli reports stats --days 7
python -m taskflow.cli data backup
```

全局 `--database 路径` 放在命令组前面。CSV 导出默认拒绝覆盖已有文件，显式 `--overwrite` 才覆盖；恢复需要备份名称、SHA-256 和 `--confirm`。
