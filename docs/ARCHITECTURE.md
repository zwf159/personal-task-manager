# 架构与模块职责

## 运行结构

HTTP 入口创建一个 Store 与 Services。Store 提供连接、事务及原有任务操作；Services 安装原有功能路由和工作台域路由。整个 HTTP 业务请求受同一可重入锁保护，避免恢复备份时混入其他请求。

命令行不启动 HTTP，通过相同服务调用校验和业务操作。跨进程写入不能由 HTTP 锁协调，因此执行命令行修改和恢复前应停止网页服务。

## 工作台业务域

`taskflow/extensions/` 下的 goals、habits、inbox、notes、planner、reviews、rules、bundles、diagnostics 分别拥有五类模块：

| 文件 | 职责 |
| --- | --- |
| schema.py | 命名、可重复执行、原子数据库迁移 |
| validation.py | 请求字段、范围、类型和领域输入校验 |
| repository.py | 参数化 SQL、持久化及统计读取 |
| service.py | 事务边界、跨表约束、幂等与冲突处理 |
| routes.py | 把 HTTP 方法和路径绑定到领域服务 |

这些模块由 Services 显式安装；并非独立服务进程。使用 Python 的命名空间子包，无需添加空的 __init__.py 文件。

共享验证在 validation.py，共享日期算法在 dates.py。assets.py 维护静态资源白名单，拒绝数据库文件、源码及任意路径读取。

## 前端

原有 app.js 负责主任务列表与表单。ui.js 提供可访问的对话框和表单构建器，所有用户文本通过 textContent 写入。

extensions.js 注册“个人工作台”并加载已声明的九个控制器及其样式；每个控制器以一个完整业务页面为单位，调用其对应 API。样式按实际页面作用域组织，产品不依赖构建工具、远程资源或第三方运行库。

## 一致性

- 任务、笔记、规则、复盘的版本校验拒绝旧编辑。
- 收集项转换、规则执行和项目模板实例化使用写事务，避免部分创建。
- 项目模板用 UUID 请求编号实现重试幂等。
- 目标读取真实任务状态；习惯同日打卡原子覆盖，不重复累加。
- 全库 SQLite 备份覆盖新增业务表；旧结构备份仍只能在结构兼容时恢复。

## 验证与文件统计

产品源码限定在 taskflow 下的 Python、JavaScript、HTML、CSS，测试、文档、数据、缓存、工具和依赖不计入。当前产品源码 112 个文件，其中 Python 与 JavaScript 合计 100 个；这是本地可复核统计，不代表外部平台已认可。

tests 使用临时真实 SQLite 文件。HTTP 测试访问随机本机端口；浏览器验收使用工作目录下的独立预览库。运行时不需要安装格式工具；格式整理所用工具不包含在仓库中。
